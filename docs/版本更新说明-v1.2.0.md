# 鹿了么 v1.2.0 版本更新说明

> **版本号**：`1.2.0`（versionCode `1000200`，buildVersion `3`）
> **发布日期**：2026-10-31
> **构建产物**：[鹿了么-v1.2.0-release未签名版.hap](<../dist/鹿了么-v1.2.0-release未签名版.hap>)（298,559 字节，release + 未签名）
> **包名**：`com.luleme.app`　**SDK**：compatible/target `6.1.1(24)`

一句话概括：**这一版补齐了「提醒」与「隐私」两块，并修掉三个体验上的刺**——切页不再有动画打架的抖动、导出的备份文件不再出现 `.json.json`、文件名自带时间戳；设置页新增定时提醒、葛神模式、防截屏保护，删除记录后 3 秒内可撤销。

## 一、Bug 修复（用户可感知）

### 1. 左右滑动切页动画「打架」

- **根因**：上一版给点击切页加了「透明度 0.86 → 1 + 上浮 6vp」的转场，这套装饰同时挂在三个页面的根容器上。手指横向滑动时，`HdsTabs` 自己的横向位移在动、页面又在淡入上浮，两个方向叠加，观感就是「抖一下 / 顿一下」。
- **修复**：删掉 `contentAlpha` / `contentOffsetY` 与三处 `.opacity().translate()`，切页交还给 `HdsTabs` 的原始横移动画；`animationDuration` 统一为 220ms。点击切页仍然即时高亮（`selectTab` 先写状态再切内容），只去掉多余修饰。
- **验证**：真机点击「日历 → 统计 → 设置」反复切换，标题与高亮同帧变化，内容不再出现半透明闪一下。

### 2. 导出备份的后缀名有时不对（`.json.json` / 无后缀）

- **根因**：`DocumentSaveOptions` 同时传了 `newFileNames: ['luleme_backup.json']` 和 `fileSuffixChoices: ['json']`，picker 会在已带后缀的名字上再追加一次；不同 ROM 版本的表现还不同。
- **修复**：只传 `newFileNames`（名字里已经带 `.json`），去掉 `fileSuffixChoices`；保存后再按真实 uri 校验一次后缀，若仍异常则在提示里带上真实文件名，便于用户自查。
- **验证**：真机picker 显示 `luleme_backup_20261031-2334.json`，确认后 toast「已导出 5 条记录」，文件正常落盘。

### 3. 导出文件名需要时间戳

- 现在固定为 `luleme_backup_YYYYMMDD-HHmm.json`（如 `luleme_backup_20261031-2334.json`）。
- 纯英文 + 数字 + 连字符，无冒号、无中文：文件会离开应用沙箱进入文件管理器 / 网盘 / 微信，避免各端对特殊字符的兼容差异。

## 二、新增功能

### 1. 定时提醒（每日）

- 位置：设置 → 提醒 → 定时提醒。
- 默认每天 **21:00**、文案「是时候鹿了！」；可改时间（系统时间选择器，24 小时制）、可改文案（800ms 防抖写入，失焦即保存）。
- 实现走系统 `reminderAgentManager`（`ReminderRequestAlarm` + `daysOfWeek: [1..7]`），由系统调度，**应用被杀 / 手机重启后依然会响**，并允许「稍后提醒」一次（5 分钟）。
- 发布前会检查通知开关，未开启时引导用户授权；授权失败则回滚开关并提示，避免「看起来开了但不会响」。
- 新增权限：`ohos.permission.PUBLISH_AGENT_REMINDER`（仅此一项，仍无网络权限）。

### 2. 葛神模式

- 位置：设置 → 提醒 → 葛神模式。
- 语义按确认的「**记录后 8 小时**」：每新增一条记录后，重建一条一次性提醒（文案「想变得和葛神一样强大吗？快来鹿吧！」）。
- 静默时段：若触发点落在 23:00–08:00，自动挪到最近的 08:00，不半夜吵人。
- 补记历史日期时按「此刻 + 8 小时」计算，避免触发时间落在过去被系统拒收。

### 3. 防截屏保护（窗口隐私模式）

- 位置：设置 → 隐私锁 → 防截屏保护，**默认开启**。
- 通过 `window.setWindowPrivacyMode(true)` 生效，覆盖截屏与最近任务缩略图；`EntryAbility` 在 `loadContent` 前与 `onForeground` 各应用一次，切换开关即时生效。
- 说明：`hdc shell snapshot_display` 这类调试通道不受该标记限制（实测仍能取到画面），所以验证请用系统截屏键（电源 + 音量下），截出来应为空白/遮罩。

### 4. 删除可撤销

- 删除确认框文案改为「删除后 3 秒内可撤销」。
- 删除后面板底部出现「已删除 1 条记录 [撤销]」条，3 秒内点击即按原时间 / 心情 / 备注重新入库；超时自动收起。
- 验证：删除 10-23 的记录 → 撤销条出现 → 点「撤销」→ 列表恢复、日历格计数回到 1。

## 三、降级策略：后台提醒不可用时

真机验证时发现，测试机（未通过 AGC 提醒能力校验）上 `publishReminder` 恒失败：

```
W foundation/Ans: ReminderControl com.luleme.app, notification not allowed.
E foundation/Ans: VerifyCloudCapability failed. uid = ..., capability = reminder_capability.
E com.luleme.app/ReminderAgentService: publish failed: 1700002 The number of reminders exceeds the limit.
```

同一份代码下普通通知（`notificationManager.publish`）可以正常弹出，说明不是通知开关问题，而是系统对「提醒」能力单独校验、且该机型校验不通过（错误码 1700002）。

因此这一版做了两层处理：

1. **不假装成功**：开关保留开启，但 toast 明确告知「当前设备不支持后台提醒，已改为打开应用时提醒」，不再把开关弹回去。
2. **应用内兜底**：首页在「到点且当天还没有记录」时显示一条提醒卡片（带「知道了」按钮）；葛神模式则在「距上一条记录 ≥ 8 小时」时显示。这样即使在能力不支持的设备上，提醒也不是空的。

> 若要真正拿到后台提醒：需要在 AGC 为应用开通「提醒」能力并改用正式证书签名后再验证。代码路径已按官方 API 写好，无需改动。

## 六、已知遗留

- 后台提醒依赖设备 / 证书的提醒能力校验，测试机上不可用（错误 1700002），已降级；需在正式签名 + AGC 能力开通后复验。
- 防截屏无法用 `hdc snapshot_display` 验证，需人工按截屏键确认。
- 提醒时间为「每天固定时刻」，暂无「每周几」选择与多组提醒。
- 应用内提醒只在打开应用时判断，不做后台唤醒。
